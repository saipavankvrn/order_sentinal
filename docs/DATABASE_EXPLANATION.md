## 1. Concurrency, WAL Mode & Performance

OrderFlow Sentinel uses SQLite with **Write-Ahead Logging (WAL)** enabled on every connection in [`backend/app/db/session.py`](file:///d:/Virtusa Jatayu/backend/app/db/session.py):

```python
@event.listens_for(engine, "connect")
def set_sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA journal_mode=WAL")
    cursor.execute("PRAGMA synchronous=NORMAL")
    cursor.execute("PRAGMA foreign_keys=ON")
    cursor.execute("PRAGMA busy_timeout=5000") # 5-second lock timeout
    cursor.close()
```

### Why WAL Mode Is Critical:
1. **Concurrent Reads and Writes**: In default rollback journal mode, writing locks the entire database file, causing `database is locked` errors during concurrent FastAPI background tasks. Under WAL mode, **readers do not block writers, and writers do not block readers**.
2. **Crash Resilience**: Committed transactions are written to the append-only `.db-wal` file before checkpointing back to `.db`, preventing corruption on power or process loss.
3. **Foreign Key Integrity**: Enforces relational consistency across `orders`, `incidents`, `approvals`, and `events`.

> [!CAUTION]  
> Never delete or reset `orderflow_sentinel.db` as a troubleshooting step. It contains 513 genuine historical orders and 57 pending approval records.

## 2. Table Schemas & Relational Mapping

### Table 1: `orders`
Primary table storing e-commerce order records and high-level progression.
- `order_id` (*VARCHAR(64)*, **PK**): Unique order identifier (e.g., `ORD-LIVE-7F3A29B1`).
- `correlation_id` (*VARCHAR(64)*, **Unique, Index**): Distributed tracing token.
- `customer_name` (*VARCHAR(128)*, **NotNull**): Customer full name.
- `customer_email` (*VARCHAR(128)*, **NotNull**): Customer contact email.
- `product_sku` (*VARCHAR(64)*, **NotNull**): SKU being ordered.
- `product_name` (*VARCHAR(256)*, **NotNull**): Human-readable product title.
- `order_amount` (*NUMERIC(10,2)*, **NotNull**): Total charge amount.
- `order_status` (*VARCHAR(32)*, **Index**): `PENDING`, `PROCESSING`, `DELAYED`, `COMPLETED`, `FAILED`.
- `current_stage` (*VARCHAR(32)*): Active stage (`CUSTOMER_ORDER`, `VALIDATION`, `INVENTORY`, `PAYMENT`, `FRAUD_CHECK`, `FULFILMENT`, `DELIVERY`, `NOTIFICATION`).
- `is_demo_order` (*BOOLEAN*, **Default False, Index**): Segregates live demo orders from historical data.
- `demo_session_id` (*VARCHAR(64)*, **Nullable, Index**): Scopes orders to a specific live demo session.
- `created_at` / `updated_at` (*DATETIME*): Timestamps.

---

### Table 2: `order_events`
Sequential, append-only telemetry records detailing every hop in the order journey.
- `event_id` (*VARCHAR(64)*, **PK**): Unique event identifier.
- `order_id` (*VARCHAR(64)*, **FK $\to$ orders.order_id**): Linked order.
- `stage` (*VARCHAR(32)*): Stage name (`VALIDATION` through `NOTIFICATION`).
- `service_name` (*VARCHAR(64)*): Microservice invoked (`payment_service`, `inventory_service`, etc.).
- `endpoint` (*VARCHAR(256)*): REST URI path invoked (e.g. `/api/v1/payments/charge`).
- `http_method` (*VARCHAR(10)*): HTTP method (`POST`, `GET`).
- `http_status` (*INTEGER*): Status code (`200`, `503`, `422`, etc.).
- `duration_ms` (*INTEGER*): Observed execution latency in milliseconds.
- `event_status` (*VARCHAR(32)*): `SUCCESS`, `FAILED`, `DELAYED`.
- `payload_summary` (*TEXT*): Serialized JSON payload snapshot.
- `timestamp` (*DATETIME*, **Index**): Exact execution timestamp.

---

### Table 3: `incidents`
Failure records detected by the deterministic detection engine.
- `incident_id` (*VARCHAR(64)*, **PK**): Incident token (e.g., `INC-8F1A29B3`).
- `order_id` (*VARCHAR(64)*, **FK $\to$ orders.order_id**): Linked failing order.
- `stage` (*VARCHAR(32)*): Stage where failure occurred.
- `service_name` (*VARCHAR(64)*): Failing service.
- `failure_category` (*VARCHAR(32)*): `API_ERROR`, `ORDER_DELAY`, `ORDER_REJECTION`.
- `failure_type` (*VARCHAR(64)*): `HTTP_503`, `SLA_BREACH`, `OUT_OF_STOCK`.
- `incident_status` (*VARCHAR(32)*): `DETECTED`, `ANALYZING`, `PENDING_APPROVAL`, `RESOLVING`, `RESOLVED`, `ESCALATED`, `REJECTED`.
- `severity` (*VARCHAR(16)*): `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`.
- `retry_count` (*INTEGER*): Number of retry attempts executed (max 3).
- `detected_at` / `resolved_at` (*DATETIME*): Lifecycle timestamps.

---

### Table 4: `rca_reports`
Advisory Root Cause Analysis reports generated by Gemini or the deterministic fallback.
- `rca_id` (*VARCHAR(64)*, **PK**): Unique RCA token.
- `incident_id` (*VARCHAR(64)*, **FK $\to$ incidents.incident_id**): Linked incident.
- `failure_category` (*VARCHAR(32)*): Diagnosed failure domain.
- `affected_service` (*VARCHAR(64)*): Service identified as the root cause.
- `observed_evidence` (*TEXT*): JSON array of string signals supporting the diagnosis.
- `probable_root_cause` (*TEXT*): Technical narrative explaining why failure occurred.
- `evidence_strength` (*VARCHAR(16)*): `HIGH`, `MEDIUM`, `LOW`.
- `recommended_action` (*VARCHAR(64)*): `RETRY_WITH_BACKOFF`, `EXPEDITE_FULFILMENT`, `SUBSTITUTE_SKU_AND_REALLOCATE`.
- `risk_level` (*VARCHAR(16)*): `LOW`, `MEDIUM`, `HIGH`.
- `model_source` (*VARCHAR(64)*): `gemini-flash-latest` or `DETERMINISTIC_FALLBACK`.

---

### Table 5: `resolution_actions`
Tracks automated or operator-directed remediation actions.
- `action_id` (*VARCHAR(64)*, **PK**): Action token.
- `incident_id` (*VARCHAR(64)*, **FK $\to$ incidents.incident_id**): Linked incident.
- `order_id` (*VARCHAR(64)*, **FK $\to$ orders.order_id**): Linked order.
- `action_type` (*VARCHAR(64)*): `RETRY_WITH_BACKOFF`, `OPERATOR_ACTION`.
- `idempotency_key` (*VARCHAR(128)*, **Unique, Index**): Cryptographic idempotency token ensuring an action is never executed twice.
- `attempt_number` (*INTEGER*): 1, 2, or 3.
- `execution_status` (*VARCHAR(32)*): `PENDING`, `EXECUTING`, `VERIFYING`, `SUCCEEDED`, `FAILED`.
- `verification_passed` (*BOOLEAN*): Whether downstream service verified state.

---

### Table 6: `operator_approvals`
Tracks Human-in-the-Loop review requests for Scenario 3.
- `approval_id` (*VARCHAR(64)*, **PK**): Approval token (e.g., `APP-5BE0BA25`).
- `incident_id` (*VARCHAR(64)*, **FK $\to$ incidents.incident_id**): Linked incident.
- `order_id` (*VARCHAR(64)*, **FK $\to$ orders.order_id**): Linked order.
- `selected_action` (*VARCHAR(64)*): Candidate action (`SUBSTITUTE_SKU_AND_REALLOCATE`).
- `action_parameters` (*TEXT*): Proposed parameters (Substitute SKU, Hub).
- `risk_level` (*VARCHAR(16)*): `HIGH`.
- `decision` (*VARCHAR(32)*, **Index**): `PENDING`, `APPROVED`, `REJECTED`.
- `operator_id` / `operator_name` / `operator_notes` (*TEXT*): Audit details.

---

### Table 7: `audit_logs`
Immutable, append-only security and operational audit trail.
- `log_id` (*INTEGER*, **PK, AutoIncrement**): Monotonically increasing sequence ID.
- `correlation_id` (*VARCHAR(64)*, **Index**): Distributed tracing token.
- `order_id` (*VARCHAR(64)*, **Nullable, Index**): Associated order ID.
- `event_type` (*VARCHAR(64)*, **Index**): `ORDER_CREATED`, `INCIDENT_DETECTED`, `RCA_COMPLETED`, `APPROVAL_REQUESTED`, `APPROVAL_DECIDED`, `RESOLUTION_VERIFIED`, `DEMO_SESSION_RESET`.
- `actor_type` (*VARCHAR(32)*): `SYSTEM`, `AI_AGENT`, `OPERATOR`, `SIMULATOR`.
- `actor_id` (*VARCHAR(64)*): Specific actor identifier (e.g. `SYSTEM:DETECTOR_ENGINE`, `OPERATOR:DEMO`).
- `summary` (*TEXT*): Human-readable audit narrative.

## 3. Safe Database Inspection & Backup

### Inspecting Active Record Counts Safely:
Execute this one-line command to query active counts without locking the file:
```powershell
.\.venv\Scripts\python.exe -c "import sqlite3; conn = sqlite3.connect('orderflow_sentinel.db'); print('Orders:', conn.cursor().execute('SELECT COUNT(*) FROM orders').fetchone()[0]); print('Pending Approvals:', conn.cursor().execute('SELECT COUNT(*) FROM operator_approvals WHERE decision = \'PENDING\'').fetchone()[0])"
```

### Backing Up the Database Safely:
Because WAL mode stores pending writes in `.db-wal`, use the SQLite backup API or copy all three files (`.db`, `.db-wal`, and `.db-shm`):
```powershell
Copy-Item "orderflow_sentinel.db" "orderflow_sentinel.db.bak"
if (Test-Path "orderflow_sentinel.db-wal") { Copy-Item "orderflow_sentinel.db-wal" "orderflow_sentinel.db-wal.bak" }
if (Test-Path "orderflow_sentinel.db-shm") { Copy-Item "orderflow_sentinel.db-shm" "orderflow_sentinel.db-shm.bak" }
```
